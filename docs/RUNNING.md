# Running the SVAMITVA scrapers

A self-serve guide, organized by state. All data collected is **aggregate** — no owner PII is
stored. No account is needed except the **captcha-gated record views** (flagged below), and the
tools never auto-solve a captcha; they pause for you.

## Setup (once)

Python 3.10+.

```bash
git clone https://github.com/SpongeBobCircleShort/svamitva-collateral-audit.git
cd svamitva-collateral-audit
pip install -r requirements.txt
```

## State cheat-sheet

| State | `--state` | Branch | Portal access | On-record charge? |
|---|---|---|---|---|
| Madhya Pradesh | 23 | `main` | ungated (session token) | **yes** (RoR col-11) |
| Chhattisgarh | 22 | `chhattisgarh` | fully open, no captcha | no (CERSAI external) |
| Gujarat | 24 | `gujarat` | cascade open, record view captcha-gated | yes (VF-7 બોજો) |
| Maharashtra | 27 | `maharashtra-scraper` | mobile + captcha gated | no (CERSAI external) |

Each state's code lives on its branch until the PRs merge to `main`; after merge everything runs
from `main`. `git checkout <branch>` first.

## The denominator (cards issued) — every state, ungated

One command, any state. Output: `data/<state>/svamitva_cards.parquet` (one row per village) plus
`…_districts.parquet`. Resumable — a re-run skips finished districts.

```bash
# whole state
python src/svamitva_scraper.py --state 22 --data-dir data/cg
```

Target a single unit by **code or partial name** (no code lookups, Hindi names work too):

```bash
python src/svamitva_scraper.py --state 23 --district Dhar --tehsil Badnawar
python src/svamitva_scraper.py --state 23 --district Bhopal --village Handia
```

`--district`, `--tehsil`, `--village` each accept a code or a case-insensitive partial name.

## Madhya Pradesh (state 23)

The reference state — the only one with the loan charge on the open record.

```bash
python src/svamitva_scraper.py --state 23 --data-dir data/mp
```

Record / charge scraping uses the webgis2 RoR and additionally needs Playwright:

```bash
pip install playwright && playwright install chromium
# then the RoR tools (src/bhulekh_api.py, src/verify_sipi.py)
```

## Chhattisgarh (state 22) — fully open

```bash
python src/svamitva_scraper.py --state 22 --data-dir data/cg
python src/cg_verify_sipi.py --sheet "SIPI index data collection - Data collection sheet.csv"
```

No captcha anywhere. Verification output: `data/cg/sipi_cg_verification.csv` (+ `_deliverable.csv`).
Add `--limit 5` for a smoke test. Rows that can't be matched are flagged "uncomparable," never guessed.

## Gujarat (state 24) — cascade open, record view gated

```bash
python src/svamitva_scraper.py --state 24 --data-dir data/gj
python src/gj_verify_sipi.py --sheet "SIPI index data collection - Data collection sheet.csv"
```

The on-record charge (બોજો) is captcha-gated. The sampler builds a frame (one village per
district), saves each captcha to `data/gj/gj_captcha.png`, and waits for you to type it:

```bash
python src/gj_sampler.py
```

## Maharashtra (state 27) — gated record view

Denominator runs like any state (`--state 27`). The Property Card record view is **mobile +
captcha** gated, so charge collection is a manual-assisted sample via `src/maha_sampler.py` — no
open census. A throwaway mobile is used (the portal only format-checks it), so no real number is
needed; you still solve the captcha.

## Reconciliation & the CERSAI route

```bash
python src/reconcile_state.py --state Gujarat --data-dir data/gj \
    --worklist data/gj/gj_worklist.csv --charge-col boja_charge
python src/build_cersai_rti.py      # -> data/rti_filled/RTI_CERSAI.md
```

Charges that never reach a state record live in **CERSAI** (the national registry). Its live search
is login+captcha+fee gated, so the lever is a single national RTI — generated by the command above.

## Good to know

- **Captcha is always yours.** The denominator and the CG/GJ verifiers need none; the samplers
  pause for you.
- **`svamitva.nic.in` is occasionally slow.** The denominator retries 3× then errors cleanly — if
  it times out, just re-run. That's the portal, not the code.
- **Everything is resumable** and writes under `data/<state>/`.
- **Aggregate only** — owner names are never persisted.
